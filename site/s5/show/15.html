Introduction

This lesson will introduce DOM, the Document Object Model.

The XML Document Object Model is a W3C specification designed to provide a standard programming interface to a wide variety of applications. XML DOM defines the way an XML document can be accessed and manipulated. Using DOM, a programmer can navigate the structure of an XML document, and add, modify, or delete its elements.

The DOM is programming language agnostic.

However, Javascript is an interesting and powerful language, and with the growing importance of web-based applications it’s a language which you should not ignore.

Javascript History

In late-1995/early-1996 a scripting language called Mocha / LiveScript was introduced as part of the Netscape v2.0 browser. It was later re-named Javascript as a marketing decision made by Netscape and Sun. The name has been a constant source of confusion; JavaScript has more in common with C (or even Lisp) than Java.

In 1997 Javascript was standardized as ECMAScript (ECMA-262). It is now supported by all major web browsers and is considered the lingua franca of client-side web programming. ActionScript, the programming language in Adobe’s Flash, is another implementation of ECMAScript.

Top 5 Javascript No-Nos

Number One – document.write:

By using document.write we circumvent the DOM and can invalidate our XHTML by inserting invalid or malformed markup. Later in the lesson we’ll see how to use the DOM to properly insert text or markup into an XHTML document.

I don’t want to see any of this in your code:

   1  <script type="text/javascript">
   2      document.write("Woot! Adding content dynamically.");
   3  </script>

Javascript No-Nos II

Number Two – Leaving out blocks:

Although most Javascript control structures can by followed by either statements or blocks, the latter should always be used.

Poor Form:

   1  if (chunky_bacon == true) 
   2      alert("Wow, this bacon sure is chunky!");

Preferred:

   1  if (chunky_bacon == true) {
   2      alert("Wow, this bacon sure is chunky!");
   3  }

Maintenance errors can be introduced when we leave out the block. Imagine we added a second alert:

   1  if (chunky_bacon == true) 
   2      alert("Wow, this bacon sure is chunky!");
   3      alert("Would you like some?");

The second alert will execute even if chunky_bacon is false.

Javascript No-Nos III

Number Three: Leaving out “var”:

All variables should be declared before used. This is done using the “var” keyword:

   1  var mountain_lion;
   2  var i, j, blade_of_grass;

The “var” keyword is not required, but it makes your programs easier to read and maintain. Variables used without being declared with “var” may end up as part of the global scope.

Global variables should be avoided if possible.

Javascript No-Nos IV

Number Four – Invalidating your XHTML

Your Javascript code may contain characters which are not allowed within an XHTML document (the ’&’ for example). For this reason we wrap our code in an XML CDATA block. (Remember to hide the open and close of the CDATA block from the Javascript interpreter by commenting out those lines.)

   1  <script type="text/javascript">
   2  // <![CDATA[
   3      // Javascript code goes here.
   4  // ]]>
   5  </script>

Javascript No-Nos V

Number Five – Leaving out semicolons:

Although semicolons are optional in Javascript it is poor form to leave them out. It is best not to rely on the automatic semicolon insertion.

Using console.log

We’ll be using Firebug’s logging console to debug our Javascript programs. The logging console frees us from having to use the Javascript alert function for debugging. Using the alert function for debugging can be annoying as it halts the flow of the program.

To write a message to the console we use the log method of the console object.

   1  console.log("An Inquiry into Meaning and Truth");

The console can also be used to inspect the properties of any object. We do this with the dir method.

   1  console.dir(object_name);

We can also inspect the contents of XML document object or XML fragments using the dirxml method.

   1  console.dirxml(xml_document_object);

Note: When deploying webpage in industry, remember to remove any console method calls when you’re done development. They can result in Javascript errors for browsers without Firebug installed.

If your console displays an error when you attempt to use console.log (“console is undefined”) you may need to upgrade to Firefox 3.

The DOM

Within the W3C DOM everything in an XML document is a node. The entire document is a document node, every tag element is an element node, the text contained within these elements are text nodes, the attributes of these elements are attribute nodes, even the XML comments are comment nodes.

The DOM represents an XML document as a tree structure. The terminology used to describe these trees is borrowed from family trees. Nodes have a hierarchical relationship to each other. DOM nodes all have one parent node (except for the root node which has no parent). Nodes can have zero or more children nodes. Nodes with the same parent are called siblings.

Everything is a Node

Consider this fragment of HTML code:

   1  <p title="The test paragraph">
   2      This is a sample of some <b>HTML you might<br/>have</b> in your document
   3  </p>

Nodes as Objects (Node Types)

When using the DOM API in a Javascript program all the DOM nodes are Javascript objects. As such, these node objects have both object properties and object methods.

Node Types

The following table lists the most commonly used node types:

   1  console.log(dom_node.nodeType);

Nodes as Objects (Node Methods)

The general node type methods are listed below:

W3C Node Method Description
appendChild(newChild) Appends newChild at the end of the child nodes for this node
cloneNode(boolean) Returns an exact clone of this node. If the boolean value is set to true, the cloned node contains all the child nodes as well
hasChildNodes() Returns true if this node has any child nodes
insertBefore(newNode,refNode) Inserts a new node, newNode, before the existing node, refNode
removeChild(nodeName) Removes the specified node, nodeName
replaceChild(newNode,oldNode) Replaces the oldNode, with the newNode
getElementsByTagName(tagName) Returns as an array all the child elements of the current element matching the "tagName" parameter.

These methods belong to all DOM node variables. So if we again have a dom_node variable that references a DOM node:

   1  // Make a copy (clone) a node
   2  var cloned_node = dom_node.cloneNode(true);

The Document Object

Within a DOM tree the entire XML document is represented as a document node. In Javascript we call this the document object. This object has some special properties and methods not available to general nodes.

W3C Document Property Returns
documentElement The root element of the document
doctype The DTD or Schema for the document.
implementation the implementation object for this particular document

Methods of the Document Object:

W3C Document Method Description
createAttribute(attributeName) Creates an attribute node with the specified attribute name
createCDATASection(text) Creates a CDATASection, containing the specified text
createComment(text) Creates a comment node, containing the specified text
createDocumentFragment() Creates an empty documentFragment object
createElement(tagName) Creates an element with the specified tagName
createEntityReference(referenceName) Creates an entityReference with the specified referenceName
createProcessingInstruction(target,text) Creates a processingInstruction node, containing the specified target and text
createTextNode(text) Creates a text node, containing the specified text
getElementById(id) Locate any element in the DOM tree via its ID attribute.

Most of these methods are used to create new DOM nodes. The general node methods can be used to add these newly created nodes anywhere within a DOM tree.

XHTML and the DOM

Since XHTML is an XML-base language we can use the DOM to interact with our XHTML documents using Javascript. In a Javascript program we access the XHTML document object via a global variable called “document”.

For example, to locate the root element of our XHTML document we could do the following:

   1  var xhtml_root_element = document.documentElement;

The documentElement property of the document object returns the root element of the XML document, in the case of XHTML this is the html element.

Note: The XHTML document we are accessing here is the document that actually contains our javascript code. For a working example of this see the no_document_write.html file in the Crossbrowser_DOM zip file.

Locating XHTML Elements

To access an array of elements of a specific tag name we can use the getElementsByTagName method of the document object.

   1  // Locate all the paragraph elements in our XHTML document.
   2  var all_p_elements = document.getElementsByTagName('p');
   3  
   4  // Dump the first p element to the console for inspection.
   5  console.log(all_p_elements[0]);

Locating XHTML nodes by ID

We can also locate individual elements if they have been assigned a unique id attribute.

Image we had an XHTML document that contained the following fragment:

   1  <div id="output">This text is a child node of the div element.</div>

To pin-point this element we could do the follow:

   1  var xhtml_output_div = document.getElementById("output");

The getElementById method of the document object searches the entire DOM tree for an element with a specific id attribute. Since id attributes are supposed to have unique values in XML/XHTML this method will always return a reference to a single DOM node.

Avoiding document.write

The document.write method was number one in our list of Javascript no-nos. For XHTML served from a web-server with the mime-type of “application/xhtml+xml” document.write will not work at all.

We need a DOM compliant method for dynamically adding text to an XHTML webpage. Let’s start with the following XHTML template.

XHTML Template

   1  <?xml version ="1.0"?>
   2  <!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Strict//EN"  
   3      "http://www.w3.org/TR/xhtml1/DTD/xhtml1-strict.dtd">
   4  <html xmlns="http://www.w3.org/1999/xhtml" xml:lang="en" lang="en">
   5  <head>
   6      <title>No More document.write</title>
   7      <script type="text/javascript">
   8          function dynamic_write() {
   9          }
  10      </script>
  11  </head>
  12  <body onload="dynamic_write()">
  13      <div id="output">
  14      </div>
  15  </body>
  16  </html>

This template contains a script element with an empty Javascript function called dynamic_write. The body element contains an onload attribute which will execute the dynamic_write function once the body element is loaded in the browser. Within the body there is an empty div element with an id attribute equal to “output”.

Creating a Text Node

As we saw in a previous section, we can pin-point the empty div element by using the following Javascript:

   1  var xhtml_output_div = document.getElementById("output");

We can then create a new DOM text node containing the string we wish to display within the empty div. We use the createTextNode method of the document object to do this.

   1  var new_text_node = document.createTextNode("Look Ma! No document.write!");

Appending a Text Node

Finally, we can append this textNode to the empty div:

   1  xhtml_output_div.appendChild(new_text_node);

For every new line we need to insert a br element:

   1  xhtml_output_div.appendChild(document.createElement("br"));
   2  xhtml_output_div.appendChild(document.createTextNode("Another line."));

This method of writing to a document can become cumbersome, so we can cheat by using the innerHTML property of node objects:

   1  var xhtml_output_div = document.getElementById("output");
   2  xhtml_output_div.innerHTML += "Look Ma! No document.write!<br/>";
   3  xhtml_output_div.innerHTML += "Another line.";

The innerHTML property used to be exclusive to Internet Explorer but is now supported by all the major browsers.

We must be careful when using innerHTML because, like document.write, it allows us to circumvent the DOM and potentially add invalid markup to our XHTML document. It’s best to avoid using innerHTML in production code, leaving it for debugging purposes only. In many cases we can simply use the Firebug console instead.

Parsing XML

So far the only document node we’ve interacted with has been the document node of our XHTML document. This node was provided to us by the browser, referenced by the document variable.

What if we want to parse an external XML document into a DOM tree and obtain its document node? I have written a method for you that does just this called loadXML.

For example, you can use this method to load the contents of an XML document into a DOM tree and obtain a reference to its document node like this:

   1  var xml_document_node = loadXML('example.xml');

Here is the loadXML function:

   1  function loadXML(filename) {
   2      var xmlDoc;
   3      if (window.ActiveXObject) {
   4          xmlDoc = new ActiveXObject("Microsoft.XMLDOM");
   5      } else if (document.implementation && document.implementation.createDocument) {
   6          xmlDoc = document.implementation.createDocument("","",null);
   7      } else {
   8          alert('Your browser does not support XML.');
   9          return;
  10      }  
  11      xmlDoc.async=false;
  12      xmlDoc.load(filename);
  13      return xmlDoc;
  14  }

You can treat this method as a black-box: You provide it with a filename and it returns to a document node object.

Printing XML Fragments

I’ve also write an xmlToString method for you that takes any type of DOM node as an argument and returns the string representation.

You can also treat this method as a black-box: You pass it a DOM node, it turns a string of XML. For example, if you had a DOM node reference by a dom_node variable:

   1  alert(xmlToString(dom_node));

Here is the xmlToString method:

   1  function xmlToString(node) {
   2      if (node.xml) { 
   3          return node.xml;
   4      } else if (XMLSerializer) {
   5          var my_serializer = new XMLSerializer();
   6          return my_serializer.serializeToString(node);
   7      } else {
   8          alert('Your browser does not support XML serialization.');
   9          return "";
  10      }
  11  }

Loading XML -- The Basics

Let’s load an XML file into a DOM tree, fetch it’s root node and then print out the contents of the root node using an alert. We will make use of our loadXML and xmlToString methods.

Here’s the Javascript:

   1  var xml_document_node = loadXML( "example.xml" );
   2  var root_element      = xml_document_node.documentElement;
   3  alert( xmlToString( root_element ) );

Adding An Element

   1  // Load an XML document:
   2  var xml_document_node  = loadXML("flight.xml");
   3  // Location the root element:
   4  var root_element       = xml_document_node.documentElement;
   5  // Create a new Element node:
   6  var new_status_element = xml_document_node.createElement("status");
   7  // Create a new Text node:
   8  var new_text_node      = xml_document_node.createTextNode("on time");
   9  // Append the new Element to the root node:
  10  root_element.appendChild(new_status_element);
  11  // Append the new Text node to the new Element:
  12  new_status_element.appendChild(new_text_node);

Multiple XML Documents

   1  // Load two XML documents: 
   2  var catalogXML   = loadXML("catalog.xml");
   3  var workorderXML = loadXML("workorder.xml");
   4  // Locate the root elements:
   5  var catalog_root_element   = catalogXML.documentElement;
   6  var workorder_root_element = workorderXML.documentElement;
   7  // Print out the contents of each root (and children):
   8  alert(xmlToString(catalog_root_element));
   9  alert(xmlToString(workorder_root_element));
  10  // Locate the first partID element in the catalog:
  11  var isolated_node = catalog_root_element.getElementsByTagName('partID')[0];
  12  // Print out the located node:
  13  alert(xmlToString(isolated_node));
  14  // Move the located node into the work order tree
  15  // as a child of the work order root node:
  16  workorder_root_element.appendChild(isolated_node);

This line:

   1  var isolated_node = catalog_root_element.getElementsByTagName('partID')[0];

Is a shortcut for:

   1  var partID_nodes = catalog_root_element.getElementsByTagName('partID');
   2  var isolated_node = partID_nodes[0];

Note: When we append the isolated_node to the work order tree it is removed from the catalog tree. This is because a node can only have one parent node.

Firefox and XML Whitespace

Unlike Internet Explorer, the FireFox browser considers whitespace (tabs, newlines, spaces, &c) in XML documents as textNodes.

This can cause problems when using child-based node properties such as childNodes, firstChild, lastChild, nextSibling, previousSibling as there will (potentially) be more children in the DOM tree in Firefox than when using IE.

When writing cross-browser code it’s best to avoid sibling/children-based methods in favour of direct targeting using IDs and classes.

You could also run any loaded XML document node through the following whitespace-node removal function:

   1  function cleanWhiteSpace(node) {
   2      var notWhitespace = /S/; // A RegExp for everything other than whitespace
   3      for (var i=0; i < node.childNodes.length; i++) {
   4          var childNode = node.childNodes[i];
   5          if ((childNode.nodeType == 3)&&
   6              (!notWhitespace.test(childNode.nodeValue))) {
   7              // that is, if it's a whitespace text node
   8              node.removeChild(node.childNodes[i]);
   9              i--;
  10          } else if(childNode.nodeType == 1) 	{
  11              // elements can have text child nodes of their own
  12              cleanWhiteSpace(childNode);
  13          }
  14      }
  15  }
